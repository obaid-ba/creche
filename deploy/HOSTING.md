# Hosting Crèche Mamati for free

Three providers, because no single free tier runs all three pieces:

| Piece | Where | Why there |
|---|---|---|
| React SPA + `/api` proxy | **Vercel** | Static hosting, and its rewrites keep the API first-party |
| Django + gunicorn | **Render** | Supabase has nowhere to run Python |
| PostgreSQL 16 | **Supabase** | Managed Postgres, 500 MB free |

The browser only ever talks to the Vercel origin. That is the load-bearing
decision in this setup — see "Why the proxy" below before changing it.

---

## 1. Supabase — the database only

1. Create a project. Region **Frankfurt** (closest free region to Tunisia).
2. Save the database password it shows you once.
3. **Project Settings → Database → Connection string** and copy both:
   - **Transaction pooler**, port `6543` → this is `DATABASE_URL`
   - **Direct connection**, port `5432` → this is `MIGRATION_DATABASE_URL`
4. **Project Settings → API → Exposed schemas**: remove `public`.
   Nothing should reach these tables except Django.
5. In the SQL editor:

   ```sql
   revoke execute on function public.rls_auto_enable() from anon, authenticated, public;
   ```

   That function is callable by anonymous visitors as shipped. It is also an
   event trigger: if it fires when Django migrates, it will enable RLS on
   Django's tables, and since Django connects as the table owner with no
   policies defined, **every list silently returns empty with no error**. If
   lists come back blank after a deploy, this is the first thing to check:

   ```sql
   select tablename, rowsecurity from pg_tables where schemaname = 'public';
   ```

Why two URLs: the pooler is required for a service that sleeps and wakes, but
it cannot run DDL reliably, so `backend/docker-entrypoint.sh` uses the direct
URL for `migrate` and the pooled one to serve.

## 2. Render — the API

**New → Blueprint →** point at this repository. `render.yaml` is read
automatically; Render builds `backend/Dockerfile` and prompts for the values
marked `sync: false`:

| Variable | Value |
|---|---|
| `DATABASE_URL` | pooled Supabase URL, port 6543 |
| `MIGRATION_DATABASE_URL` | direct Supabase URL, port 5432 |
| `DJANGO_ALLOWED_HOSTS` | `creche-api.onrender.com` |
| `CSRF_TRUSTED_ORIGINS` | `https://<your-project>.vercel.app` |
| `CORS_ALLOWED_ORIGINS` | same as above (unused behind the proxy; set it anyway) |

`DJANGO_SECRET_KEY` and `ACCESS_CODE_HMAC_KEY` are generated by Render and
must never be edited afterwards. Rotating the HMAC key invalidates every
access code in the database and locks out every family.

`DJANGO_ALLOWED_HOSTS` is this service's hostname, not Vercel's, because
Vercel's proxy rewrites `Host` to the destination. `CSRF_TRUSTED_ORIGINS` is
Vercel's, because the proxy forwards `Origin` unchanged.

Check `https://creche-api.onrender.com/api/health/` before moving on.

## 3. Vercel — the SPA

**Root directory: `frontend`.** Vite is detected; the build needs no
configuration.

**Set no environment variables.** `VITE_API_BASE_URL` defaults to `/api`
(`frontend/src/services/client.ts`), which the proxy in
`frontend/vercel.json` forwards to Render. Setting it to the `.onrender.com`
URL is the one change that breaks login — see below.

After the first deploy, put the real Vercel hostname into
`frontend/vercel.json`'s rewrite if it is not `creche-api.onrender.com`, and
into `CSRF_TRUSTED_ORIGINS` on Render.

---

## Why the proxy

`frontend/src/services/tokenStore.ts` holds the access token in a
module-scoped variable and never in `localStorage`, because this application
holds children's records and web storage is readable by any script that
achieves XSS. The consequence: **the httpOnly refresh cookie is the entire
session across a page reload.**

Point the SPA directly at `creche-api.onrender.com` and that cookie becomes
third-party. `SameSite=Strict` (the default in
`backend/config/settings/base.py`) never sends it cross-site, and Safari and
iOS block third-party cookies regardless of `SameSite`. The symptom is
specific and easy to misread: login appears to succeed, then every reload
lands on the login page — and it fails on iPhones while working in Chrome on
a laptop.

Routing `/api` through Vercel makes the cookie first-party, so `Strict`
keeps working, no CORS preflight happens, and there is nothing to configure.

## The free tier's one real cost

Render's free plan sleeps after 15 minutes idle and takes ~50 seconds to
wake. The first parent to open the app each morning waits almost a minute
and may well assume it is broken. Fine for showing the client; not fine for
staff using it daily. Render's starter plan removes it.
